# Versio Reverse — 設計書（v0.4 草案）

Noise Engineering Versio 用カスタムファームウエア「クロック同期リバース」の設計書です。
**v0.3（リバース）は実装・実機確認済み。v0.4 で追加するコムフィルター（§3.7）は議論中の草案です。** 「設計OK」の合意が得られるまで実装には着手しません。

---

## 1. 目的

- 入力音声をピッチ変化なしで逆再生する
- 外部クロック（2PPQN 想定）に同期して逆再生区間を区切り、**逆再生されたトランジェントをビートに合わせる**
- ツマミ（＋CV）でドライ音／リバース音をスイッチのように切り替える
- 逆再生時のトランジェント位置をツマミで前後に微調整できる

## 3. 機能仕様

### 3.1 全体方針：リバースエンジンは常時動作

リバースエンジンは **モードに関係なく常にバックグラウンドで動作** し、クロック同期・オフセット適用済みのリバース音を生成し続ける。
モード切替は「どちらの信号を出力するか」を選ぶだけである。

```
 常時: 入力 ──▶ [リングバッファ] ──▶ [クロック同期リバース（オフセット適用）] ──▶ Wet
 出力: モード = DRY ? 入力(Dry) : Wet     （切替時 2ms フェード）
```

これにより、ユーザーの切替操作がビートとずれていても、**切り替えた瞬間に聞こえるリバース音は常にビートに揃っている**（区間の途中から聞こえ始める）。

| モード | 出力 |
|---|---|
| DRY | 入力をそのまま出力（Dry 100% / Wet 0%） |
| REVERSE | リバース音のみ出力（Dry 0% / Wet 100%） |

- ミックス（クロスフェード）は持たない。スイッチのように切り替える
- クリック防止のため切替時のみ **2ms のフェード** を入れる（聴感上はスイッチ）
- DRY → REVERSE、REVERSE → DRY ともに即時

### 3.2 リバース方式（クロック同期リバース）

入力は常にリングバッファに録音し続ける。区間の開始時刻（クロック時刻）を `t_k` とすると、
次の区間開始までの間、**直前に録音された音を過去に向かって等速（×1.0）で読む**。

```
読み出し位置(t) = 2·t_k − t + d        （d = オフセット、§3.3）
```

- 読み出し速度は −1.0 倍固定 → **ピッチ変化なし**（整数サンプル読み出し、補間不要）
- 区間長 = 1 クロック間隔（2PPQN なので 8 分音符 1 つ分）
- 「直前の 1 クロック分の音」が逆順で再生され、区間頭のトランジェントは **次のクロックに向かって盛り上がり、次のクロックの位置に来る**
- 区間の切り替わりは新旧 2 つの読み出しヘッドを 5ms クロスフェードしてクリックを防ぐ
- 区間開始は「実クロック」または「仮想クロック」（§3.5）で行う

### 3.3 トランジェント合わせ用オフセット（-350ms〜+350ms）

| d | 挙動 | 実装 |
|---|---|---|
| d > 0（遅らせる） | 逆再生トランジェントが d だけ後ろにずれる | 区間の切替時刻を `t_k + d` にし、読み出し位置は上式のまま |
| d = 0 | トランジェントが次のクロック位置に来る | — |
| d < 0（早める） | 逆再生トランジェントが \|d\| だけ前にずれる | 読み出し窓を \|d\| だけ過去にずらす（区間はクロックで切替） |

- **±350ms の両方向とも実現可能**（どちらも過去の音だけで作れる）
- ツマミ中央 = 0ms。中央付近に ±3% 程度のデッドゾーンを設けて 0ms に合わせやすくする
- `d` は **区間開始時にラッチ** する（区間の途中で変えると読み出し位置が飛んでクリックになるため）
- `|d|` がクロック間隔を超える場合（2PPQN で BPM 約 86 以上 → 間隔 350ms 以下）、ずれ量は実質「`|d|` をクロック間隔で割った余り」として聞こえる。**ms 指定のまま回り込みを許容する**（制限・割合指定はしない）

### 3.4 バッファ長とメモリ

- **オーディオバッファ：6000ms**（6.0s × 48kHz × 2ch × 4byte ≈ 2.3MB、SDRAM に配置。64MB に対して十分余裕）
- 読み出し位置と書き込み位置の距離（遅れ）は最大 `2P + |d|`。
  区間長 P は §3.5 により最大 600ms に制限されるので、最大遅れは `2×600 + 350 = 1550ms` → 6000ms で十分

### 3.5 クロック処理

#### 前提
- 2PPQN、最低 BPM 50 → **最大有効クロック間隔 `T_MAX = 600ms`**
- ゲート入力をオーディオコールバック内で **サンプル単位でポーリング** し、立ち上がりをサンプル精度で検出
- 内部に「現在のクロック間隔 `T`」を持ち、実クロックが来ない間は **仮想クロック** を `T` ごとに発生させて区間を進める

#### ルール

| # | 状況 | 動作 |
|---|---|---|
| 0 | 起動直後（実クロック未受信） | `T = 500ms`（BPM60 の 2PPQN）で仮想クロックを発生して動作。最初の実クロックはルール 2 扱い（位相リセットのみ）、2 発目で `T` を決定 |
| 1 | 実クロック受信（前回の実クロックからの間隔 Δ ≤ 600ms） | `T = Δ` に更新。この時刻から新しい区間を開始 |
| 2 | 実クロック受信（Δ > 600ms：クロック途絶からの復帰など） | `T` は据え置き。この時刻から新しい区間を開始（位相はリセット）。次の実クロックとの間隔でルール 1 により `T` を決め直す |
| 3 | 前回の区間開始から `T` 経過しても実クロックが来ない | 仮想クロックを発生し新しい区間を開始（最後の間隔で動作継続） |
| 4 | 仮想クロックの直後（`T` の 20% 以内）に実クロックが来た | テンポが少し遅くなっただけとみなし、区間開始を実クロック時刻に **付け直す**（極端に短い区間を作らない）。Δ はルール 1/2 で判定 |

- ルール 1・2 の組み合わせが「短い間隔なら最後と新しいクロックで設定し直し／長い間隔なら新しいクロックとその次で決め直す」に対応する
- 実クロックは常に仮想クロックより優先（実クロックが来た瞬間に位相を合わせる）
- 最短間隔：チャタリング対策として 2ms 以内の連続エッジは無視。間隔 20ms 未満は 20ms として扱う
- クロックが 1 発だけ抜けて間隔が 2 倍（≤600ms）になった場合も、ルールどおり新しい間隔として採用する（仕様として許容）

```
実クロック:  |    |    |    |              ×途絶×            |    |
仮想クロック:                  :    :    :    :    :
区間:        [ ][ ][ ][ ][ ][ ][ ][ ][ ][ ][ ][ ][ ][ ][ ][ ]
                             ↑最後の間隔 T で継続      ↑復帰: 位相リセット、次で T 再計測
```

### 3.6 モード切替（リバース ON/OFF）

- 切替ツマミ＋CV（加算値）が **50% を境に** DRY / REVERSE を切り替える
- CV・ツマミのノイズでばたつかないよう **ヒステリシス**（例: 52% で ON、48% で OFF）
- ツマミ 0 のとき CV が約 2.5V を超えると REVERSE（0/5V のゲート信号でそのまま切り替え可能）

### 3.7 コムフィルター（v0.4 追加・草案）

中高域の grit / shimmer を加えるエフェクト。**モード切替（DRY/REVERSE）の後段** に置き、原音・リバース音のどちらも処理する。

#### 信号処理

入力 `x`（モード切替の出力）を 500Hz で **高域 `h` と低域 `l` に分け**、高域だけに遅延音を加える。

```
h   = HPF_500Hz(x)          # 2 次バターワース（12dB/oct）、固定
l   = x − h                 # 相補分割（l + h = x が厳密に成り立つ）
y   = l + g · ( h + w · h(t − τ_ch) )
```

- 遅延音は `h`（500Hz 以下をカットした音）を遅らせたもの → 「ディレイ音は 500Hz 以下をカット」を満たす
- フィードバックなし
- ツマミ 0% では `w = 0, g = 1` → `y = l + h = x`（**原音と完全に一致**）

#### ミックス（KNOB_3）

| KNOB_3 | Dry:Wet（振幅比） | L/R ディレイ差 |
|---|---|---|
| 0% | 100 : 0 | 0 |
| 0〜50% | Wet が 0 → Dry と同じ大きさまで増える（`w = m / 0.5`） | 0 |
| 50% | 50 : 50（Dry と Wet が同じ大きさ = コムの効きが最大） | 0 |
| 50〜100% | 変わらない | 0 → 最大（`s = (m − 0.5) / 0.5`） |

#### 音量とクリップ対策

同じ大きさの Dry と Wet を単純に足すと、
- コムの山では振幅が **2 倍（+6dB）** → 大きな入力ではクリップする
- 平均的な音量（パワー）は **+3dB**

逆に Dry と Wet を 0.5 ずつにすると、クリップはしないが **Wet に低域が無いので 500Hz 以下が −6dB** になり、痩せて小さく聞こえる。

**提案：高域だけに補正ゲイン `g = 1 / √(1 + w²)` をかける**
- 低域 `l` は常にそのまま → 低音が痩せない
- 高域の平均音量は Wet を足しても変わらない（50% で g ≈ 0.71 = −3dB）
- 高域の山の最大値は `g·(1 + w)` = 1.41 倍（+3dB）に抑えられる（単純加算の +6dB から半減）
- それでも残る最大 +3dB のピークに備え、**出力段にソフトクリッパー**（−3dBFS 付近から緩やかに飽和）を安全装置として置く

参考：一般的な ±5V のモジュラー音声は Versio の入力フルスケール（約 ±8V）より約 4dB 小さいので、+3dB のピークなら通常はソフトクリッパーまで届かない。

#### ディレイタイム（基準 τ：0.1〜8ms）

- ツマミの変化を **指数カーブ** に割り当てる（0.1→8ms は 80 倍の範囲。コムの音程感は 1/τ で決まるので、指数カーブだとツマミの回転と音の変化が均等に感じられる）
- 0.1ms = 4.8 サンプルなので **小数サンプルの遅延が必要**。3 次（Hermite）補間で読む
- τ は約 20ms で平滑化してジッパーノイズを防ぐ（CV で速く動かした場合は、その分フランジャー的に変化する）

#### ステレオ幅（KNOB_3 50〜100%）

L と R のディレイタイムを基準 τ の前後に振り分ける：

```
τ_L = τ − s · Δmax / 2
τ_R = τ + s · Δmax / 2      （τ_L の下限 0.05ms）
```

- 左右でコムの山と谷の位置がずれ、「片方で谷の周波数がもう片方では山」になることで広がって聞こえる
- 山と谷がちょうど入れ替わる周波数は `f = 1 / (2Δ)`。Δ = 0.5ms で 1kHz、0.25ms で 2kHz
- **提案：Δmax = 0.5ms**（HPF の 500Hz のすぐ上、1kHz から上の帯域全体で左右が異なる）
- 比率（τ の ±x%）ではなく ms 固定にする理由：τ = 0.1ms のとき ±25% でも差は 0.025ms しかなく、ほとんど広がらないため
- Dry は左右同じなので定位の中心は保たれる。Δ が 1〜1.5ms を超えると、モノラルにまとめたときのコム感が強くなる
- Δmax は定数にして、実機で 0.3〜1.0ms の範囲を聴き比べて決める

#### 処理負荷

1 チャンネルあたり HPF（2 次）1 回、遅延線の読み出し（補間）1 回。遅延線は 1 チャンネル 512 サンプル（約 10.7ms）で、CPU・メモリともにごくわずか。

## 5. 信号処理フロー

```
 In L/R ──┬───────────────────────────────────────────────┐
          │                                               │ (Dry)
          ▼                                               ▼
   [リングバッファ 6s, SDRAM]                       ┌──────────┐
          │                                        │ モード    │
          ▼                                        │ 切替      │
   [読み出しヘッド A/B（逆方向×1.0）]──(Wet)─────▶│ (2ms fade)│
   [区間切替クロスフェード 5ms]                     └────┬─────┘
          ▲                                             │
 Gate ─▶ [立ち上がり検出] ─▶ [クロック管理(実/仮想)] ─▶ t_k, d ラッチ
                                                        ▼
 KNOB_0+CV ─▶ [ヒステリシス 48/52%] ─▶ モード切替   [コムフィルター §3.7]
 KNOB_1+CV ─▶ [デッドゾーン → d]                        │
 KNOB_3+CV ─▶ ミックス w / ステレオ幅 s ──────────────▶│
 KNOB_?+CV ─▶ 基準ディレイ τ（指数カーブ）────────────▶│
                                                        ▼
                                               [ソフトクリッパー] ──▶ Out L/R
```

- L/R は同じクロック・同じ読み出し位置で処理（ステレオリンク）
- サンプルレート 48kHz、ブロックサイズ 48
- リバースエンジン・クロック管理はモードに関係なく常時動作

## 8. 制約・リスク

| リスク | 対策 |
|---|---|
| 区間境界・モード切替でのクリック | 5ms / 2ms の短いフェード |
| 入力のトランジェントがクロックより遅れる（楽器の立ち上がり等） | オフセット d で調整 |
| クロックのテンポ変化・ジッター | 実クロックで毎回位相リセット、間隔は毎回更新 |
| クロックが 1 発だけ抜けた場合、間隔が 2 倍（≤600ms）なら誤ってテンポ半分と解釈される | 仕様として許容（次のクロックで正しい間隔に戻る） |
| ADC ノイズで 50% 付近がばたつく | ヒステリシス |
| KNOB 番号と物理位置の対応が不明 | 実機確認 |
