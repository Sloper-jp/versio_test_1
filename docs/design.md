# Versio Reverse — 設計書（草案 v0.1）

Noise Engineering Versio 用カスタムファームウエア「クロック同期リバース」の設計書です。
**本書は議論用の草案です。** 「未決事項」（§9）が確定するまで実装には着手しません。

---

## 1. 目的

- 入力音声をピッチ変化なしで逆再生する
- 外部クロックの立ち上がりから逆再生を開始する（ビート同期）
- ツマミ（＋CV）でドライ音／リバース音をスイッチのように切り替える
- 逆再生時のトランジェント位置をビートに合わせるため、再生タイミングをツマミでずらせる

## 3. 機能仕様

### 3.1 動作モード

| モード | 出力 |
|---|---|
| DRY | 入力をそのまま出力（Dry 100% / Wet 0%） |
| REVERSE | リバース音のみ出力（Dry 0% / Wet 100%） |

- ミックス（クロスフェード）は持たない。**スイッチのように切り替える。**
- ただし完全な瞬時切り替えはクリックノイズが出るため、**2ms 程度のクリック防止フェード**を入れる（聴感上はスイッチ）。→ 未決事項 Q5

### 3.2 リバース方式（クロック同期リバース）

入力は常にリングバッファに録音し続ける。クロックの立ち上がり時刻を `t_k` とすると、
次のクロック `t_{k+1}` までの区間で **直前に録音された音を、現在位置から過去に向かって等速（×1.0）で読む**。

```
読み出し位置(t) = 2·t_k − t + d        （d = オフセット、§3.3）
```

- 読み出し速度は −1.0 倍固定 → **ピッチ変化なし**
- 結果として「直前の 1 クロック分の音」が逆順で再生され、区間頭のトランジェントは **次のクロックの直前に向かって盛り上がる**（典型的なリバースの"吸い込み"）
- 区間長 `P` はクロック間隔そのもの。事前に周期を知る必要はない（次のクロックが来たら次の区間へ）
- 区間の切り替わりでは新旧 2 つの読み出しヘッドを約 5ms クロスフェードしてクリックを防ぐ

### 3.3 トランジェント合わせ用オフセット（-350ms〜+350ms）

オフセット `d` をツマミで設定する。**±350ms の両方向とも因果的に実現可能**（未来のサンプルは不要）。

| d | 挙動 | 実装 |
|---|---|---|
| d > 0（遅らせる） | リバース出力全体を d だけ後ろにずらす | 区間の切替時刻を `t_k + d` にし、読み出し位置は上式のまま |
| d = 0 | クロックと同時にリバース区間が切り替わる | — |
| d < 0（早める） | 逆再生されたトランジェントが |d| だけ早く来る | 読み出し窓を |d| だけ過去にずらす（区間はクロックで切替） |

- ツマミ中央 = 0ms。中央付近に ±3% 程度のデッドゾーンを設けて 0ms に合わせやすくする
- `d` は **クロック受信時にラッチ**する（区間の途中で変えると読み出し位置が飛んでクリックになるため）

### 3.4 バッファ長とメモリ

読み出し位置と書き込み位置の距離（遅れ）は最大で `2P + |d|` になる。

| 条件 | 必要バッファ長 |
|---|---|
| 指定どおり バッファ 600ms | 最大区間長 `P ≤ (600 − |d|) / 2` → **d=0 でも 300ms、d=±350ms で 125ms まで** |
| 提案：最大区間長 600ms、d=±350ms | `2×600 + 350 = 1550ms` → **バッファ 2.0 秒** |

- 600ms バッファだと 120BPM の 4 分音符（500ms）すら逆再生できない。
- **提案：「最大リバース区間 600ms」を仕様とし、内部バッファは 2 秒を SDRAM に確保する**（2.0s × 48kHz × 2ch × 4byte ≈ 768KB。SDRAM 64MB に対して余裕）。→ 未決事項 Q1

### 3.5 クロック処理

- ゲート入力をオーディオコールバック内で **サンプル単位でポーリング**し、立ち上がりをサンプル精度で検出（ブロック単位 1ms の揺れを避ける）
- FSU ボタンも手動クロック（押した瞬間に立ち上がり）として OR する（案）
- クロック間隔が最大区間長（600ms）を超えた場合 → 未決事項 Q3
- クロックが来ない／止まった場合 → 未決事項 Q4

### 3.6 モード切替（リバース ON/OFF）

- 切替ツマミ＋CV（加算値）が **50% を境に** DRY / REVERSE を切り替える
- CV・ツマミのノイズでばたつかないよう **ヒステリシス**（例: 52% で ON、48% で OFF）
- ツマミ 0 のとき CV が約 2.5V を超えると REVERSE（ゲート信号 0/5V でそのまま切り替え可能）
- REVERSE に切り替えた瞬間の挙動 → 未決事項 Q2

## 5. 信号処理フロー

```
 In L/R ──┬─────────────────────────────────────────────┐
          │                                             │ (Dry)
          ▼                                             ▼
   [リングバッファ 2s, SDRAM]                     ┌──────────┐
          │                                      │ モード    │──▶ Out L/R
          ▼                                      │ 切替      │
   [読み出しヘッド A/B（逆方向×1.0）]──(Wet)───▶│ (2ms fade)│
   [区間切替クロスフェード 5ms]                   └──────────┘
          ▲
 Gate/Tap ─▶ [立ち上がり検出(サンプル精度)] ─▶ t_k, d ラッチ
```

- L/R は同じクロック・同じ読み出し位置で処理（ステレオリンク）
- 読み出しは整数サンプル単位（速度が常に −1.0 なので補間不要）

## 8. 制約・リスク

| リスク | 対策 |
|---|---|
| 600ms バッファでは区間長が最大 300ms | バッファ 2 秒に拡大（§3.4, Q1） |
| 区間境界・モード切替でのクリック | 5ms / 2ms の短いフェード |
| 入力のトランジェントがクロックより遅れる（楽器の立ち上がり等） | オフセット d で調整 |
| クロック周期が変化・ジッター | 区間は実際のクロック到着で切り替えるので追従する |
| ADC ノイズで 50% 付近がばたつく | ヒステリシス |
| KNOB 番号と物理位置の対応が不明 | 初期ビルドで LED による確認モードを用意し実機確認 |

## 9. 未決事項（議論したい点）

**Q1. バッファ長**
600ms バッファだと最大リバース区間は 300ms（d=0 時）です。
「リバース区間を最大 600ms」とし内部バッファを 2 秒にする案でよいですか？
（それとも 600ms はバッファ容量そのものの指定で、区間 300ms 上限で問題ない？）

**Q2. REVERSE に切り替えた瞬間の挙動**
- (a) 即座に「今」から過去に向かって逆再生を開始し、次のクロックで同期（反応が速い）
- (b) 次のクロックまで DRY のまま待ち、クロックから REVERSE（常にビート頭から揃う）
- (c) 次のクロックまで無音
また、DRY に戻すのは即時でよいですか？

**Q3. クロック間隔が最大区間長（600ms）を超えたとき**
- (a) 600ms で自動的に次の区間へ（内部で仮想クロックを発生）
- (b) 同じ区間を最初からループ
- (c) 無音で次のクロックを待つ
- (d) クロック分割（SW で ÷1/÷2/÷4 等）を用意して利用者に合わせてもらう

**Q4. クロックが無い／止まったとき**
- (a) 最後に計測した周期で自走
- (b) 固定の周期（例: 500ms）で自走
- (c) リバースしない（DRY を出す）

**Q5. 切替のクリック防止フェード**
2ms 程度のフェードを入れてよいですか？（完全な瞬時切替だとクリックが出ます）

**Q6. 余っているツマミ 5 個・トグル 2 個の使い道**（不要なら未使用）
候補:
- クロック分割／逓倍（トグル: ×2 / ×1 / ÷2 など）
- リバース区間長をクロックの 1/2, 1/4 に（トグル）
- 区間境界クロスフェード時間（ツマミ）
- 出力レベル（ツマミ）
- リバース音のみにフィードバック／ディケイ

**Q7. ステレオ**
L/R リンク（同じタイミング）でよいですか？

**Q8. サンプルレート**
48kHz（既定）でよいですか？（96kHz でもメモリ的には可能）
